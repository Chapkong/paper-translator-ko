# 그림 영역 크롭과 인용 블록 들여쓰기 — 설계

작성 2026-09-09. 계기: Teece 2007 추출이 품질 게이트에 걸려 번역이 시작되지 못했다
(잘린 문단 0.131 > 상한 0.05).

## 배경

`명령서.md`는 이미 옳은 방침을 규정하고 있다.

> 92: **그림·표·연구모형**: 페이지에서 해당 영역을 200dpi로 잘라 이미지로 넣는다.
> 93: **그림 안 글자**: 잘라낸 영역의 텍스트는 본문에서 뺀다.

명세는 맞고 구현이 못 따라간다. 방침을 바꾸지 않고 코드를 명세에 맞춘다.

## 결함 A — 크롭 폭을 캡션에서 추정한다

`scripts/figures.py: _column_bounds()`는 크롭 영역의 좌우를 **캡션이 속한 단**에서 가져온다.
캡션 폭이 페이지의 60% 미만이면 한쪽 단으로 한정한다. 그런데 전면 다이어그램의 캡션은
대개 가운데에 짧게 놓이므로, 그림보다 좁은 캡션이 그림 폭을 결정해 버린다.

실측 (Teece 2007, 페이지 폭 564pt, 전폭 판정 기준 338pt):

| 페이지 | 캡션 폭 | 크롭 영역 x | 그림 라벨 실제 x | 결과 |
|---|---|---|---|---|
| p17 Figure 2 | 171pt | 38~377 | 332~455 | 오른쪽 절반이 본문으로 유입 |
| p23 Figure 3 | 230pt | 40~491 | 384~436 | 잘림 — 단, 우연이다 |

p23이 통과한 것은 왼쪽 단 그룹에 폭 넓은 줄 하나가 섞여 `max(x1)`이 491까지 끌려간
덕분이다. 같은 입력에서 두 그림의 운명이 갈렸다는 사실 자체가 이 추정이 불안정하다는 증거다.

유입된 라벨은 본문 문장 한가운데에 박힌다. `work/…/source.md:351-353`:

```
…the judicious use of bankruptcy laws to

Cospecialization rewrite uncompetitive supply contracts that…
```

### 수정

크롭 영역의 좌우를 캡션이 아니라 **그림 실물**에서 정한다. `page.get_drawings()`의 벡터
도형 bbox와 페이지 이미지 블록 bbox 중 캡션에 인접한 것들을 모아 실제 잉크 범위를 구하고,
캡션 단 경계와 합집합을 취한다. 잉크가 없으면(순수 텍스트 표) 지금의 캡션 단 경계로 되돌아간다.

검토했으나 택하지 않은 대안:

- **그림은 무조건 페이지 전폭** — 단폭 그림 옆의 본문까지 삼킨다. 반대 방향 손상이다.
- **캡션 위에 넓은 줄이 있으면 확장** — 지금 p23이 우연히 통과한 것과 같은 종류의
  간접 신호에 다시 기댄다.

## 결함 B — 인용 블록 가드가 절대 좌표를 ±1.5pt로 본다

`scripts/post.py: build_oracle()`의 `same_indent_run`은 들여쓴 줄이 연달아 같은 위치에
오면 첫 줄만 문단을 열도록 막는다. 판정식이 `abs(prev.x0 - line.x0) <= 1.5`다.

두 가지가 어긋난다.

**B-1. 오차가 스캔 지터보다 좁다.** Teece는 스캔본이라 같은 인용문 안에서 x0가 흔들린다.
p29 Porter 인용문 실측: `66.5 → 68.6 → 67.2 → 65.4 → 69.0 → 67.3` (최대 3.6pt).
6줄 중 5줄에서 가드가 실패해 줄마다 문단이 열렸다. 단어 한가운데가 갈라지기도 했다 —
`…change manage` / `ment. Although…`.

**B-2. 단·페이지 경계를 못 넘는다.** 절대 x0를 빼기 때문에 인용문이 단을 넘어가면
차이가 폭만큼 벌어진다. p20 실측: x0 71.5(edge 57) → 300.6(edge 288), 차이 229.8pt.
들여쓰기끼리 비교하면 14.5 vs 12.6으로 사실상 같은 줄인데도 무조건 실패한다.

### 수정

판정을 **단 기준선 대비 들여쓰기**로 바꾸고 오차를 넓힌다.

```
abs(prev.x0 - line.x0) <= 1.5           →   abs(prev_indent - indent_gap) <= QUOTE_INDENT_TOL
```

`QUOTE_INDENT_TOL = 3.0`pt. 근거: 실측 지터 최대 3.6pt이나 그 값은 단 경계를 넘는
p20 사례를 포함하며, 같은 단 안에서는 최대 3.6pt(65.4↔69.0)다. 3.0pt는 관측된 지터를
대부분 흡수하면서 진짜 문단 들여쓰기(INDENT_PT 6.0pt 이상)와는 겹치지 않는다.

## 일반성

두 수정 모두 Teece 전용 분기를 만들지 않는다. 캡션 추측 대신 실제 잉크 좌표를 읽고,
절대 좌표 대신 조판이 실제로 쓰는 상대 들여쓰기를 읽는다. 앞으로 들어올 다른 조판에도
같은 신호가 그대로 적용된다.

## 검증

`python scripts/selftest.py` — pytest는 도입하지 않는다.

1. **회귀 없음**: 이미 통과한 3편의 추출 지표가 나빠지지 않아야 한다.
   기준선(변경 전 실측) — Peteraf 보존율 1.006 / 잘린 문단 0.014,
   Noda·Bower 0.996 / 0.016, Mintzberg는 별도 측정.
2. **Teece 게이트 통과**: 잘린 문단 비율 0.131 → 0.05 이하.
3. **결함별 단위 테스트**: `selftest.py`에 두 개를 더한다.
   - 전면 그림 + 좁은 캡션 픽스처에서 크롭 영역이 그림 전체를 덮는가
   - x0가 3pt 흔들리고 단을 넘어가는 인용 블록이 한 문단으로 유지되는가

## 구현 중 드러난 것

설계 당시 결함 A·B만 보았으나, 그 둘을 고치자 가려져 있던 결함 셋이 드러났다.
Teece의 잘린 문단 비율이 0.131에서 단계마다 어떻게 내려갔는지 함께 적는다.

### A-2. 스캔본에는 도형 좌표가 없다 (0.131 → 0.087)

설계는 `page.get_drawings()`로 그림 실물을 재려 했다. 그런데 Teece p17에서 `_ink_bbox`가
None을 돌려주었다 — 스캔본이라 벡터 도형이 0개고, 유일한 이미지는 전면 스캔이라
`MAX_GRAPHIC_RATIO`에 걸러진다. `명령서.md` 92행이 말한 바로 그 경우다.

그때 남는 신호는 **그림 안 글자**다. 본문보다 작고 좁아 `_is_prose`가 이미 걸러낸 것들이다.
영역의 y밴드 안에서 이 글자들을 모아 좌우로 넓힌다(`_figure_extent`). 멀리 떨어진 글자는
같은 그림이 아니므로 `GROW_GAP`(40pt) 안에 닿는 것만 차례로 흡수한다.

### A-3. 본문 크기가 두 값으로 갈린다 (0.087 → 0.065)

`_is_prose`가 p17의 본문 네 줄을 그림으로 오판해 영역 위쪽 경계가 본문 한가운데에 걸렸다.
Teece는 텍스트 레이어가 크기를 정수로 양자화해 본문이 8pt(52%)와 9pt(35%)로 갈리는데,
중앙값 8.0에 대해 9.0은 1.125배라 기본 범위(1.12배)를 간발로 벗어난다. 전체 줄의 35.8%다.

처음에 `BODY_HI`를 1.16으로 넓혔더니 Noda·Bower에서 표 행이 본문으로 읽혀 잘린 문단이
0.016 → 0.024로 나빠졌다. **임계값을 뭉뚱그려 넓히는 것은 답이 아니었다.** 대신 문서가
실제로 많이 쓰는 크기만 본문으로 인정한다(`body_band`, `COMMON_SIZE_RATIO` 20%).
크기가 연속값인 문서는 최빈 크기가 14%에 그쳐 범위가 그대로 유지된다 — Noda·Bower와
Peteraf는 기준선으로 복귀했다.

### C. 쪽 번호가 제목이 되어 문장을 가른다 (0.065 → 0.056)

p25 상단 6% 지점의 `1342`가 `## 1342`로 승격되어 문장 한가운데에 끼었다. 반복 판정으로는
못 잡는다 — `repeat_norm('1342')`은 `#`이 되지만 다른 쪽 러닝헤드는 `# d. j. teece`라
서로 다른 항목이 된다. 위·아래 여백(8% 바깥)에 숫자만 홀로 있는 줄은 버린다.

### D. `Figure N)`이 캡션으로 오인된다

`…it can earn (see` / `Figure 4). Furthermore,…`가 갈렸다. `build_oracle`은 `CAPTION_RE`
정규식만 보므로 `figures.is_caption()`이 걸러내는 오탐을 그대로 통과시킨다.

처음에는 "앞 문장이 끝났을 때만 캡션"으로 막았는데, 이번엔 Peteraf의 **진짜 캡션**이
앞 조각에 붙어 0.014 → 0.027로 나빠졌다. 진짜 캡션도 그림 축 라벨 바로 뒤에 오므로
앞 줄이 문장부호로 끝나지 않는다(`Diversification` / `Figure 4. The determination of…`).
둘을 가르는 것은 **닫히지 않은 괄호**다 — 상호참조는 앞 줄이 열어둔 `(`를 닫는다.

### 남은 것

Teece에 아직 잘리는 문단이 남는다. 성격이 다르고 게이트를 넘기는 데 필요하지 않아
이번 범위에 넣지 않았다.

- 표지의 로고 OCR 찌꺼기(`%% oiVc^Tv^vrv^^v^`, `* lnf?rSc??Tic??`)가 제목으로 승격
- 인용 부호 없는 짧은 인용문 한 건
- 수식이 단 경계에서 갈림
- 하이픈 분리 87곳(`outsourc ing`, `orga nizati`) — 게이트에는 걸리지 않는다
