# 그림·표 이미지화와 페이지 넘김 문장 잇기 — 설계

작성일: 2026-09-04 · 대상: `paper-translator/` · 승인: David Lee

## 1. 배경

첫 완역 실행([2026-09-04-완역-충실도-개선](2026-09-04-완역-충실도-개선-design.md) 적용본)의 결과물을 검토한 결과 두 가지 문제가 남았다.

**그림 자리에 OCR 잔재가 들어온다.** 스캔본 PDF는 그림이 페이지 이미지의 일부라 별도 이미지로 추출되지 않는다. 그림 안의 글자만 텍스트 레이어에 남아 본문에 섞인다.

```
Industry High Cost Firm Low Cost Firm
p S2 ~~ ~ ~~~~~AC AC
.~~~~- - - - - - -- -- - - .- .... . - -- - - - ~~---- / A C
기업 내부의 비용에 의한 불완전 이동성 … 3 hose cpia경쟁 그림 3. 경쟁우위의 초석
```

**페이지를 넘어 이어지는 문장이 끊긴다.** 실측 9건이다.

```
…which involve collective learning and are knowledge-based, are
   → enhanced as they are applied. Such resources may provide…
```

원인은 각주를 페이지 끝으로 모으면서 생겼다. 본문 문단이 각주 블록에 막혀 닫히고, 다음 쪽의 이어지는 부분이 별도 문단이 된다. 번역자는 그 조각을 독립된 문단으로 받으므로 문장이 끊긴 채 번역된다.

## 2. 목표

- 그림·표·연구모형을 **원문 모양 그대로 이미지로** 결과물에 넣는다.
- 그림 영역의 OCR 잔재를 본문에서 없앤다.
- 페이지·단을 넘어 이어지는 문장을 하나의 문단으로 잇는다.

**비목표**: 캡션 없는 그림 탐지, 수식 이미지화, 그림 내부 글자의 번역.

## 3. 설계

### 3-1. 그림·표 영역 이미지화 — `scripts/figures.py` (신규)

스캔본에서는 그림을 따로 뽑을 수 없으므로 **PDF 페이지의 해당 영역을 200dpi로 렌더링**한다(`page.get_pixmap(clip=rect, dpi=200)`). 원문 모양이 그대로 남고, 그 영역의 텍스트 줄을 본문에서 빼면 OCR 잔재도 함께 사라진다.

**표 영역**은 `page.find_tables()`가 주는 bbox를 4pt 여유를 두고 자른다. 마크다운 표 변환(`post._merge_tables`)은 걷어낸다 — 사용자가 표도 이미지로 받기를 택했다.

**그림 영역**은 캡션을 기준으로 잡는다. 캡션 판정은 `^(Figure|Table|그림|표)\s*\d+\s*[.:)]` 정규식에 더해 아래 셋 중 하나를 만족해야 한다. 본문 속 `Figure 2.) Increased production by additional` 같은 오탐을 걸러내기 위한 조건이다.

| 조건 | 실측 근거 |
|---|---|
| 캡션 글자가 본문보다 작다(본문 중앙값의 0.95배 이하) | Figure 1·2 캡션 7.6·7.8pt vs 본문 8.31pt |
| 위쪽에 15pt 이상 빈 공간이 있다 | Figure 3 위 34pt |
| 단 중앙에 놓여 있다(왼쪽 여백이 단 폭의 15% 이상) | Figure 1 x0=163, 단 기준선 45 |

자를 범위는 캡션 위쪽으로 올라가며 **본문 문단에 속하는 줄**(정답지의 문단 시작 이후 이어지는 줄)을 만나면 멈춘다. 그림 속 잔재 줄은 문단에 속하지 않으므로 영역 안에 들어온다. 가로는 캡션이 페이지 폭의 60%를 넘으면 페이지 폭, 아니면 해당 단 폭이다. 높이가 40pt 미만이면 그림이 없다고 보고 건너뛴다.

**애매하면 자르지 않는다.** 잘못 자르면 본문이 이미지 속으로 사라져 번역에서 통째로 빠진다. 실측에서 `Figure 4`는 조건에 걸리지 않아 놓치지만, 오탐 2건을 막는 대가로 받아들인다.

이미지 링크는 캡션 문단 바로 앞에 놓는다. 캡션 자체는 텍스트로 남아 번역된다. 기존 삽입 이미지 추출(면적 3~60%)은 유지하되, 잘라낸 영역 안에 든 이미지는 중복이므로 제외한다.

### 3-2. 페이지 넘김 문장 잇기 — `post.merge_continuations`

문단 목록을 훑어 **문장부호 없이 끝난 본문 문단** 뒤의 첫 본문 문단이 **소문자로 시작하면** 둘을 잇는다. 사이에 낀 각주 블록·이미지 링크는 버리지 않고 합쳐진 문단 뒤로 옮긴다. 앞 문단이 하이픈으로 끝나면 기존 규칙대로 공백 없이 붙인다.

**제목이 사이에 끼면 잇지 않는다.** 절이 바뀌는 자리는 문단도 실제로 끝나는 자리다. 소문자 시작 조건이 안전장치다 — 새 문단은 대문자나 인용부호로 시작한다.

## 4. 테스트

**합성 픽스처.** 3쪽 픽스처에 도형과 `Figure 1.` 캡션, 도형 안에 잔재 줄을 그려 넣고 확인한다 — 잘린 PNG가 생기는가, 영역 안 잔재가 본문에서 빠졌는가, 캡션은 텍스트로 남는가. 문장 잇기는 마침표 없이 끝나는 문단과 소문자로 시작하는 다음 문단을 만들어 병합을 확인한다.

**Peteraf 회귀.** 그림 이미지 3개 이상 생성, `p S2 ~~`류 잔재 0건, 페이지 넘김 절단 9건 → 0건, 잘린 문단 비율 하락.

**sample.pdf 회귀.** 표가 마크다운 대신 이미지로 나오고 기존 그림 2개가 유지되는지 확인한다.
