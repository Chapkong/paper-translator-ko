# 실측 기록

실제 논문으로 돌려 얻은 수치와, 각 논문이 드러낸 결함을 남긴다. 다음에 같은 실수를
반복하지 않기 위한 기록이다. 코드 변경 근거는 각 커밋 메시지에 있다.

## 1. Peteraf (1993), SMJ — JSTOR 2단 스캔본, 14쪽

첫 실전 논문. MVP가 "ALL PASS"를 보고했으나 **원문의 3분의 1이 없었다.**

| 항목 | 개선 전 | 개선 후 |
|---|---|---|
| 문자 보존율 | 0.686 | 1.006 |
| 잘린 문단 비율 | 0.903 | 0.014 |
| 추출된 원문 | 37,175자 | 50,148자 |
| JSTOR 푸터·러닝헤드 | 14회 잔존 | 0회 |
| 각주 | 본문에 혼입 | 23개 분리·표시 |
| 그림 | 유실(실은 로고 2장) | 3개 잘라내 이미지로 |

**드러난 것**

- 검증이 "깨진 원문"을 기준으로 삼고 있었다. `verify.py`는 청크와 번역문만 대조하므로
  원문 자체의 손상을 볼 수 없다. 검수 보고서는 절단된 문장을 "원문과 동일하게 대응됨"으로
  기록했다 — 3중 안전망이 같은 맹점을 공유했다.
- 블록 경계를 문단 경계로 믿을 수 없다. 실제 저널 PDF는 한 문단이 여러 블록으로 쪼개진다
  (`minor points.`가 별도 블록). 조판 신호(첫 줄 들여쓰기, 짧은 마지막 줄)를 봐야 한다.
- 스캔 텍스트 레이어는 줄마다 글자 크기가 흔들린다(본문 7.65~9.07pt, 중앙값 8.31).
  크기만으로 제목을 가르면 본문 줄이 제목이 된다.
- 보존율만으로는 순서 오류를 못 본다. 좌우 단이 한 줄에 섞이면 문자는 그대로라
  보존율이 1.0에 가깝지만 잘린 문단 비율이 치솟는다(0.577).

**번역 결과** — 29청크 기준이 아닌 12청크. 각주 25개 중 17개가 영어로 남았는데
`output-verifier`가 PASS를 냈다. 이 사건이 `final_check.py`(기계 최종 검증)를 만든 계기다.

## 2. Noda · Bower (2007), SMJ — 35쪽, 13만 자 필드 연구

표 9개와 프로세스 매트릭스 3개가 있는 논문. 추출 게이트가 처음에 0.46(잘린 문단)으로 막았다.

| 항목 | 최초 | 최종 |
|---|---|---|
| 문자 보존율 | 0.948 | 0.996 |
| 잘린 문단 비율 | 0.460 | 0.016 |
| 그림·표 이미지 | 0개 | 7개 |
| 청크 수 | — | 29개 |
| 번역 소요 | — | 53분 (18:00~18:53) |

**드러난 것**

- **인용 블록이 문단마다 끊긴다.** 인터뷰 인용문은 모든 줄이 같은 위치로 들여써 있는데
  (본문 x0=267, 인용문 279) "들여쓴 줄 = 문단 첫 줄" 규칙이 매 줄에 발동했다.
  같은 위치로 이어지면 첫 줄만 문단을 열어야 한다. 이 하나로 0.46 → 0.19.
- **표 캡션은 표 위에 붙는다.** 그림과 반대다. 캡션 위쪽만 훑으면 표가 하나도 안 잡힌다.
- 표 머리행은 본문과 크기·폭이 같다. 본문은 여러 줄 이어지므로 연속 3줄일 때만 본문으로
  판정해야 한다. 수치 토큰이 3개 이상인 줄은 표 행으로 본다.
- **콜론으로 끝나는 문장은 잘린 게 아니다.** 학술문은 인용을 도입할 때 콜론으로 끝난다
  (`as he recalled:`). 지표가 이걸 절단으로 세어 오탐이 쏟아졌다.
- 그림·표로 옮긴 글자를 보존율 분모에서 빼야 한다. 이미지로 옮긴 것이 유실로 집계됐다.
- **프로세스 매트릭스가 본문으로 샜다.** p19·p25 영역이 매트릭스 아래쪽 일부만 덮었다
  (116·120pt vs 실제 370pt). 매트릭스 칸에는 글머리표가 붙으므로 그 신호로 가른다.

**운영 중 발견**

- 추출 게이트가 미달로 막았는데도 번역이 진행됐다(32청크 중 25개). 커맨드에 중단 규칙이
  적혀 있어도 실행 중에 지켜지지 않는다. 지시문이 아니라 구조로 막아야 한다.
- 그 실행이 **실행 중에 `extract.py`를 고쳐** 작업 폴더 이름을 밑줄로 바꿨다. app.py는
  원래 이름으로 폴더를 찾아 진행률이 1/5에서 멈췄다. 폴더 이름 규칙을 `post.work_stem`
  한 곳으로 모아 해결했다. 오케스트레이터의 `Edit` 권한을 빼는 것은 아직 하지 않았다.
- 기계 검증은 FAIL(미번역 본문 7건)인데 `output-verifier`는 PASS를 냈다. 규칙대로라면
  되돌려 고쳐야 하는데 산출물이 나왔다.

**일회성 결과물 수복 (2026-09-07)**

위 7건은 번역할 문장이 아니라 그림 칸 글자(`Be.South Redefinition Continual Impetus…`)였다.
재번역 없이 다음을 직접 처리했다. **따라서 납품된 `ko.md`는 파이프라인을 새로 돌린 결과와
완전히 같지 않다.** 같게 만들려면 전체 재실행이 필요하다(약 53분).

1. `figures.py` 수정 후 그림 7개를 새 영역으로 다시 렌더링
2. `translated/013.md`·`018.md`에서 그림 조각 문단 제거
3. 각주 조각에 갈려 있던 문장을 이어 붙임 —
   `두 회사의 무선 사업 지지자는 1984, skyrocketed from $40-60 per POP…` +
   `Strategic Context Structural Context * … 자사 최고경영진의 관심을 끌고…`
   → `두 회사의 무선 사업 지지자는 자사 최고경영진의 관심을 끌고 … 대조적인 경험을 하였다.`
4. 재조립 → HTML 재생성 → 기계 검증 PASS

## 3. sample.pdf — 자체 생성 1단 문서, 3쪽

회귀 확인용. 그림 2개와 표 1개가 계속 나오는지 본다. 표는 이미지로 잘린다.

## 남은 문제

- 오케스트레이터가 게이트 실패와 기계 검증 FAIL을 무시할 수 있다. 지시문으로는 막히지
  않으므로 구조를 바꿔야 한다.
- 오케스트레이터에게 `Edit` 권한이 있어 실행 중 파이프라인 코드를 고칠 수 있다.
- 캡션이 없는 그림은 잘라내지 못한다.
- Peteraf `Figure 4`처럼 조건에 걸리지 않는 캡션은 놓친다(오탐 방지를 위한 의도적 선택).
