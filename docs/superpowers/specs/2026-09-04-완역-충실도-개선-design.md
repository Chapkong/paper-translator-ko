# 논문 번역기 완역 충실도 개선 — 설계

작성일: 2026-09-04 · 대상: `paper-translator/` · 승인: David Lee

## 1. 배경 — 왜 고치는가

첫 실전 논문(Peteraf 1993, SMJ, JSTOR 2단 조판)을 돌린 결과, 파이프라인은 "ALL PASS"를 보고했으나 실제로는 실패한 실행이었다.

| 증상 | 측정값 |
|---|---|
| 추출 단계 원문 손실 | 원문 raw text 55,659자 → `source.md` 37,175자 (보존율 약 67%) |
| 문장 절단 | 초록이 문장 중간에서 끊김, 단어 반토막(`ous strands` ← vari\|ous), 좌우 단 교차로 참고문헌 뭉개짐 |
| 각주 혼입 | 각주가 본문 문단 사이에 삽입됨 (`I This is not meant to suggest…`) |
| 보일러플레이트 | JSTOR 푸터가 `source.md`에 14회, 번역본에 12회 잔존 |
| 이미지 유실 | 추출 이미지가 다른 폴더에 저장되어 `meta.json`은 `figures: 0`, HTML에 깨진 `<img>` 2개 |

근본 원인은 두 가지다.

1. **레이아웃 판단을 pymupdf4llm에 통째로 위임했다.** PDF 자체는 멀쩡한 디지털 문서다. 같은 논문을 KorDocAI CLI(`npx kordoc --no-tables`)로 뽑으면 보존율이 0.972로 올라가고 JSTOR 푸터·러닝헤드가 0회가 된다. 도구의 한계가 아니라 도구 선택의 문제였다.
2. **검증이 "깨진 원문" 기준이었다.** `verify.py`는 청크와 번역문만 대조하므로 원문 자체의 손상을 볼 수 없다. 번역자·검수자도 손상된 입력을 충실히 번역했고, 검수 보고서는 절단된 문장을 "원문과 동일하게 대응됨"으로 기록했다. 3중 안전망이 전부 같은 맹점을 공유했다.

부가로, 청크 병렬 번역 구조상 **문서 전체를 읽는 주체가 없다.** 번역자도 검수자도 청크 하나만 본다. 청크 경계의 지시어와 문서 전체 관점의 역어 적절성은 설계상 검사되지 않는다.

## 2. 목표와 비목표

**최우선 목표는 원문 그대로의 완전한 문장으로 번역되는 것이다.** 속도·비용은 그 다음이다.

- 저널 2단 조판 디지털 PDF에서 원문 손실 없이 읽기 순서를 복원한다.
- 손실이 남으면 번역을 시작하지 않고 멈춘다.
- 조립 후 문서 전체를 통독해 문맥·역어 적절성을 점검하고 고친다.
- 사용자가 규칙을 직접 수정할 수 있는 명령서를 남긴다.

**비목표(이번 범위 밖)**: 수식 OCR(KorDocAI `--formula-ocr`), 스캔 PDF OCR(`--ocr`), Marker/MinerU 도입, DOCX 추출 경로 변경, 표 복원 고도화, 그림 내부 캡션 OCR. 앞의 둘은 KorDocAI 옵션으로 언제든 켤 수 있으므로 필요해질 때 켠다. 대상이 2단 저널 PDF로 확정되었으므로 지금 치를 값이 아니다. 3단·수식 논문이 실제로 들어오면 그때 PDF 경로만 교체한다.

## 3. 설계

### 3-1. 추출기 — KorDocAI CLI + 후처리

**레이아웃 재구성은 직접 짜지 않고 KorDocAI CLI에 맡긴다.** 실측 근거:

| 경로 | 문자 보존율 | JSTOR 푸터 | 러닝헤드 |
|---|---|---|---|
| 현행 pymupdf4llm | 0.686 | 14회 | 잔존 |
| `npx kordoc <pdf> --no-tables` | **0.972** | 0회 | 0회 |

`--no-tables`가 필수다. 기본값에서는 2단 조판의 테두리를 표로 오인해 좌우 단이 한 줄에 섞이고 본문이 가짜 마크다운 표로 뭉개진다(도구 자체 문서에도 `#64`로 기재된 알려진 동작).

CLI는 npm 패키지(`npx -y kordoc`)이므로 `extract.py`에서 서브프로세스로 호출한다. MCP로 부르면 결과가 대화 컨텍스트를 통과해 논문 1편당 2만 토큰 이상을 쓰지만, CLI 호출은 토큰이 들지 않고 재현 가능하다.

KorDocAI가 해결하지 못하는 부분만 `scripts/post.py`가 후처리한다.

1. **문단 복원** — KorDocAI 출력은 PDF의 한 줄이 한 문단이다(1,037문단 중 80자 초과는 120개뿐). PyMuPDF 블록의 **첫 줄 집합을 문단 시작 정답지**로 삼아 줄을 잇는다. 블록 경계가 곧 문단 경계이므로 들여쓰기 추측이 필요 없다.
2. **하이픈 분철 결합** — `communi-
cation` → `communication`. 현재 61곳 남아 있다.
3. **각주 표시** — PyMuPDF에서 얻은 줄별 폰트 크기를 정답지로 써서, 본문 중앙값의 0.85배 이하인 줄을 각주로 판정해 `> **각주 N**` 형태로 감싼다. KorDocAI는 각주를 이미 페이지 끝에 순서대로 모아두므로 위치 이동은 필요 없다.
4. **표지 배너 제거** — 첫 페이지의 JSTOR 약관·접근성 안내 문단을 버리고 서지 정보만 남긴다.
5. **이미지 선별** — KorDocAI가 남긴 이미지 링크 15개는 전면 스캔 배경이다. PyMuPDF로 면적 3~60%이면서 한 페이지에만 등장하는 이미지만 골라 저장하고 링크를 다시 건다. (실측: 로고 0.62%·1.71%, 전면 스캔 91.32%, sample.pdf 실제 그림 12.99%)

출력 계약(`source.md`, `images/`, `meta.json`)은 불변이므로 `chunk.py`·`assemble.py`·`to_html.py`는 손대지 않는다.

**폴백 경로**는 기존 pymupdf4llm 경로를 그대로 쓴다. KorDocAI CLI가 없거나(오프라인 npx) 점수가 미달이면 기존 경로로 재시도해 점수가 높은 쪽을 채택한다.

### 3-2. 손실 게이트 — 추출 직후

`source.md`를 원문과 대조해 두 지표로 채점한다.

| 지표 | 정의 | 기준 |
|---|---|---|
| 문자 보존율 | (재조립 본문 + 각주) ÷ (제거 대상을 뺀 raw 텍스트) | ≥ 0.97 |
| 잘린 문단 비율 | 문장 부호 없이 끝나는 문단 ÷ 전체 문단 | ≤ 3% |

분모의 "제거 대상"은 반복 요소(러닝헤드·푸터·배너)와 표지 약관 문단이다. 의도적으로 버린 텍스트가 손실로 집계되지 않도록, 게이트는 제거된 블록의 문자 수를 따로 기록해 분모에서 뺀다.

미달이면 **기존 pymupdf4llm 경로로 재추출해 점수가 높은 쪽을 채택**하고, 그래도 미달이면 `work/<stem>/extract_report.md`에 페이지별 점수와 의심 구간을 남기고 **exit 1로 중단한다**. `/translate`는 여기서 멈추므로 손상된 원문에 번역 토큰을 태우지 않는다. app.py는 프로세스 종료 + HTML 부재를 이미 `failed`로 표시하므로 UI 변경은 불필요하며, 사용자는 "로그 보기"로 리포트를 확인한다.

### 3-3. 각주 배치

KorDocAI가 각주를 이미 해당 페이지 본문 뒤에 번호순으로 모아둔다. **위치를 옮기지 않고 표시만 붙인다** — `> **각주 2** …` 형태로 감싸고 번역 대상에 포함한다. 본문 흐름을 끊지 않으면서 원문 정보를 유실하지 않는다는 목적은 그대로 달성되고, 위치 재배치 로직이 필요 없어진다.

각주 판정은 PyMuPDF에서 얻은 줄별 폰트 크기(본문 중앙값의 0.85배 이하)로 한다. **폰트 크기를 모르는 줄은 본문으로 간주한다** — 본문을 각주로 오판해 인용 블록에 가두는 쪽이 더 나쁘다.

### 3-4. 전문 통독 — `reviewer` 이후, 조립 후 (신규 단계)

조립된 `ko.md` 전문과 `glossary.md`를 통째로 읽는 에이전트를 1회 실행한다. 원문 전체를 다시 넣지 않고, 의심되는 대목만 해당 원문 청크를 열어 대조한다.

점검 대상:
- 청크 경계의 흐름 — 지시어("이 결과는…")가 가리키는 대상이 실제로 앞에 있는지
- 용어 흔들림 — 같은 개념이 앞뒤로 다르게 번역됐는지
- 문맥상 역어 적절성 — glossary 역어가 그 문장에서 실제로 맞는지
- 어색한 문단 — 단어 교체를 넘어 문단째 다시 쓰는 것까지 허용한다

**수정 반영은 두 갈래로 분류한다.**

| 분류 | 처리 | 예 |
|---|---|---|
| 명확 | 자동 반영 후 보고 | 용어 흔들림 통일, 지시어 연결 수정, 번역투 |
| 판단 필요 | 목록으로 뽑아 사용자 확인 | 역어 선택이 갈리는 용어 (`fungible resource` → 대체 가능 자원 / 전용 가능 자원) |

**수정은 `ko.md`가 아니라 `translated/NNN.md`에 적용한다.** 통독 에이전트는 전체 문맥을 파악하기 위해 조립된 `ko.md`를 읽지만, 고칠 때는 해당 청크 파일을 수정한다. 청크가 단일 원천으로 유지되어야 `verify.py`의 청크 대조 검사가 계속 유효하고, 재조립이 언제든 반복 가능하다. 따라서 단계 순서는 `assemble → 전문 통독 → verify 재실행 → assemble 재실행 → to_html`이 된다.

산출물은 `work/<stem>/final_review.md`(변경 표 + 확인 요청 목록)이다.

### 3-5. 결과물 검증 — `output-verifier` (최종 관문)

지금 구조에는 완성된 결과물을 **원문과 대조해 합격 여부를 판정하는 주체가 없다.** `verify.py`는 구조만 보고, `reviewer`는 청크 하나만 보며, `final-reviewer`는 번역본 안쪽의 문맥만 본다. 지난 실행이 "ALL PASS"를 보고하고도 실패했던 이유가 이것이다.

조립·통독이 끝난 뒤 `output-verifier` 서브에이전트가 최종 산출물을 검사하고 `work/<stem>/verdict.md`에 **PASS 또는 FAIL**을 적는다. 점검 항목은 다음과 같다.

- **완결성** — `source.md`의 절 제목과 문단이 번역본에 모두 대응되는가. 통째로 빠진 절이 없는가.
- **문장 완결성** — 잘린 문장, 비문, 조사 오류가 없는가.
- **수치·인용** — 표본 20건을 원문과 직접 대조한다(`verify.py`의 기계 검사가 놓치는 문맥상 오류를 본다).
- **용어 일관성** — glossary 역어를 따르는가.
- **각주·그림** — 개수와 위치가 원문과 맞는가. HTML에 깨진 이미지가 없는가.
- **문체** — 학술 서술체가 일관되는가. 개조식·구어체가 섞이지 않았는가.
- **창작 금지** — 원문에 없는 내용이 추가되지 않았는가.

**판정자는 수정하지 않는다.** 도구를 `Read`·`Grep`으로 제한해 역할을 분리한다. FAIL이면 `verdict.md`에 어느 청크를 어떻게 고칠지 지시를 남기고, 오케스트레이터가 해당 청크만 `translator`/`reviewer`로 되돌린 뒤 재조립·재검증한다. **최대 2회** 반복하고 그래도 FAIL이면 사용자에게 사유와 함께 보고하고 멈춘다.

이로써 파이프라인의 검사는 세 층이 된다 — 기계 검사(`verify.py`), 청크 검수(`reviewer`), 문서 검토(`final-reviewer`), 그리고 그 위에 결과물 판정(`output-verifier`)이다. 앞의 셋은 고치는 역할이고 마지막 하나는 합격을 결정하는 역할이라는 점에서 성격이 다르다.

### 3-6. 사후 수정 경로

납품 후 사용자가 용어·표현 변경을 요청하면, glossary를 갱신하고 해당 표현을 전 문서에서 일괄 교체한 뒤 재조립·재렌더링한다. 이때 번역을 처음부터 다시 하지 않는다. 명령서에 절차와 요청 형식을 기재한다.

### 3-7. 번역 검증 강화 — `verify.py`

기존 검사(이미지 링크 문자열, 헤딩 수, 표 행 수, 한글 비율, 영문 잔존)에 네 가지를 추가한다.

- **이미지 파일 실존** — 링크 문자열이 아니라 파일이 실제 존재하는지 확인한다. 이번 유실이 통과된 구멍이다.
- **숫자 집합 대조** — 원문의 4자리 연도와 소수점 포함 수치는 FAIL로 잡는다. `four conditions → 네 가지 조건`처럼 정상적으로 한글 수사가 되는 경우가 있으므로 그 외 정수는 WARN으로 보고만 한다.
- **인용 집합 대조** — `(Author, YYYY)` 표기의 누락·변형을 검사한다.
- **문단 수 1:1** — 문단이 통째로 증발하는 유형의 누락을 잡는다.

### 3-8. 명령서 — `명령서.md` (신규)

사용자가 직접 읽고 고치는 단일 규칙 문서. 현재 규칙은 `.claude/commands/translate.md`, `.claude/skills/academic-korean/SKILL.md`, 에이전트 정의 3곳에 흩어져 있어 어디를 고쳐야 할지 알 수 없다. 다음을 한 곳에 모은다.

- 파이프라인 절차와 각 단계의 책임
- 문체·용어 규칙(완역 서술체, 역어 하나·병기 한 쌍)
- 각주 배치, 보일러플레이트 처리 방침
- 손실 게이트 임계값(0.97 / 3%)
- 전문 통독의 자동/확인 분류 기준
- 사후 수정 요청 방법
- **불편사항 기록란** — 사용하다 걸린 점을 한 줄씩 적어두면 다음 개선 작업의 입력이 된다

`CLAUDE.md`에 "이 폴더의 모든 작업은 명령서.md를 따른다"를 걸어 매 실행마다 자동으로 읽히게 하고(app.py가 `cwd=paper-translator`로 실행), 커맨드·에이전트 정의에도 명령서를 먼저 읽으라고 명시해 이중으로 건다. 임계값을 바꾸려면 명령서와 스크립트 상수를 함께 고친다.

### 3-9. 곁가지 수정

`extract.py:95`·`chunk.py:70`의 `write_text(json.dumps(...))`에 인코딩이 빠져 Windows cp949로 저장된다(`meta.json`의 한글 경로가 깨져 있음). 한글 제목 논문에서 app.py의 진행률 표시가 무너지는 원인이며, 어차피 두 파일을 수정하므로 함께 고친다.

## 4. 테스트

pytest가 설치되어 있지 않고 프로젝트가 `python scripts/x.py` 스타일이므로, 의존성 없는 `scripts/selftest.py` 하나로 간다.

**단위 — 정답을 아는 합성 PDF.** PyMuPDF로 2단 본문 + 각주 + 러닝헤드 + 하이픈 분철 + 반복 푸터를 심은 3쪽 PDF를 직접 그리고, 후처리 결과가 원래 문장과 정확히 일치하는지 확인한다. 문단 복원·하이픈 결합·각주 판정·이미지 선별을 각각 독립으로 검증한다. KorDocAI CLI 자체는 우리 코드가 아니므로 테스트하지 않고, 어댑터가 CLI 부재를 감지해 폴백하는지만 확인한다.

**회귀 1 — Peteraf.** 보존율이 배너·약관 제외 기준 97% 이상으로 오르고 잘린 문단이 사실상 0이 되는지 확인하고, 앞 3쪽을 원문 PDF와 눈으로 대조한다.

**회귀 2 — sample.pdf.** 1단 문서와 그림 2·표 1이 기존과 동일하게 나오는지 확인한다. 새 경로가 되던 것을 깨지 않았다는 증거다.

## 5. 완료 기준

- [ ] Peteraf 문자 보존율 ≥ 0.97, 잘린 문단 ≤ 3%
- [ ] `source.md`에 JSTOR 푸터·러닝헤드 0회
- [ ] 각주가 본문 문단 사이에 삽입되지 않고 `> **각주 N**`으로 표시됨
- [ ] 로고 이미지가 `output/`에 포함되지 않고, 남은 이미지는 HTML에 base64로 임베드
- [ ] `selftest.py` 전 항목 통과, sample.pdf 회귀 통과
- [ ] 전문 통독 산출물 `final_review.md` 생성, 확인 요청 목록이 최종 보고에 노출
- [ ] `output-verifier`가 `verdict.md`에 PASS를 기록(FAIL이면 최대 2회 재수정 후 사용자 보고)
- [ ] `명령서.md` 작성, `CLAUDE.md`에서 참조
